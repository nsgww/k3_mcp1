# k3_mcp1 语音控制 WebSocket 接口说明

服务：`k3-mcp1.service`（`/opt/k3_mcp1/09_asr_llm_ws.py`）
地址：`ws://<板子IP>:8060`

## 1. 连接路径

| 路径 | 用途 | 音频来源 |
|---|---|---|
| `/stream` | 客户端推麦克风流 | 客户端上行 PCM |
| `/stream/multicast` | 组播音频输入 | 组播组（默认 `224.2.1.168:6020`，可用 `?group=&port=` 指定） |
| `/stream/local_mic` | 板载麦克风 | 服务端采音（当前 `AUTO_LOCAL_MIC=0` 已关闭自动采集） |

查询参数：`group`、`port`（组播地址）；`auto=1`（仅服务端内部客户端使用，见下文角色规则）。

## 2. 组播连接的角色：单主（owner）+ 订阅（display）

同一个 `group:port` 只允许**一条**控制管线（入组收音频 + 唤醒门控 + ASR/LLM/工具执行）：

- **owner**：先到先得；`AUTO_MULTICAST` 保留组（当前 `224.2.1.213:6020`）只允许带 `auto=1` 的内部客户端当 owner，外部连接一律为订阅。
- **display（订阅）**：不入组、不唤醒、不执行指令；只收 owner 扇出的事件与 TTS 音频。发送 `set_multicast_group` / `wake_gate` 会被拒绝并返回错误。
- owner 断开或被顶替（`replaced by multicast owner`）后，后续新连接才可接任 owner。
- 因此同时开多个网页**不会**重复执行指令。

## 3. 上行消息（客户端 → 服务端）

| 类型 | 格式 | 说明 |
|---|---|---|
| 音频帧 | 二进制 | PCM int16 单声道 16kHz（`/stream` 路径；组播路径音频来自组播组，客户端无需上行音频） |
| `ping` | JSON | 心跳，回 `pong` |
| `end` | JSON | 结束当前收音并立即处理（仅无门控/手动模式） |
| `wake_gate` | JSON | 开关唤醒门控（display 连接不可用） |
| `set_multicast_group` | JSON `{group, port}` | 切换收听组播组（仅 owner；目标组被占会拒绝） |
| `mcp_status` / `mcp_refresh` / `mcp_config` | JSON | 查询/刷新/修改 MCP 连接 |
| `kws_keywords` | JSON | 查询/更新唤醒词 |
| `config` | JSON | 运行时参数调整 |

## 4. 下行消息（服务端 → 客户端）

### 4.1 事件类（JSON）

| type | 关键字段 | 时机 |
|---|---|---|
| `status` | `message` | 连接建立、处理进度（"收到，正在理解..." / "正在执行..." 等） |
| `wake_state` | `state`: `idle`/`woken`/`listening`/`processing` | 门控状态每次切换 |
| `kws` | `keyword`, `message` | 唤醒词命中（`wake_only: true` 表示只播报不进 LLM） |
| `asr` | `text` | 指令识别结果 |
| `llm` | `text`, `done` | LLM 流式输出片段与结束 |
| `function` | — | 工具调用事件 |
| `mcp_status` / `mcp_config` / `kws_keywords` | — | 对应上行查询的应答 |
| `done` | — | 一轮处理结束 |
| `error` | `message` | 错误 |

### 4.2 语音播报（TTS）

每条语音播报 = **一条 JSON + 紧跟一包二进制 wav**：

```json
{
  "type": "tts",
  "format": "wav",
  "sample_rate": 16000,
  "channels": 1,
  "sample_width": 2,
  "byte_length": 32204,
  "text": "我在"
}
```

- `text` 即播报文字，可直接用于界面显示；
- **唤醒应答「我在」额外带 `"wake_ack": true`**，这是它与其他播报（"好的，正在处理"、"已执行：开灯" 等）的唯一区别；
- wav 文本长度由 `byte_length` 给出，随后二进制帧送达；
- 订阅（display）连接同样能收到全部 TTS 播报（owner 扇出）。

### 4.3 唤醒应答时序示例

```
唤醒词命中 →
  {"type":"wake_state","state":"woken"}
  {"type":"kws","keyword":"你好军哥","message":"..."}
  {"type":"tts", ... "text":"我在","wake_ack":true}  + <wav 二进制>
用户说指令 →
  {"type":"wake_state","state":"listening"}
  {"type":"wake_state","state":"processing"}
  {"type":"asr","text":"开灯。"}
  {"type":"status","message":"收到，正在理解..."}
  {"type":"tts", ... "text":"好的，正在处理"} + <wav>
  （工具调用执行）
  {"type":"tts", ... "text":"已执行：开灯"} + <wav>
  {"type":"done"}
  {"type":"wake_state","state":"idle"}   ← one-shot：需重新唤醒
```

## 5. 行为注意事项

- **唤醒应答静音窗**：唤醒命中后约 1.05 秒（「我在」0.7s + 0.35s 余量）内上行音频被整帧丢弃，用于防止喇叭回采误触发。**用户应等「我在」播完再说指令**，否则短指令（如「开灯」）开头会被吞掉。
- **one-shot 模式**：每次控制完成后门控回 `idle`，必须重新说唤醒词。
- **TTS 组播回投**：组播输入模式下，播报同时发往 `TTS_MULTICAST_GROUP:PORT`（当前 `224.2.1.179:6020`）供硬件音源播放。
- **处理期间丢帧**：一轮处理完成后会丢弃积压的陈旧组播帧，从最新音频继续（`mcast.flush()`）。
- **超时**：唤醒后 5 秒无语音自动回待机；单句最长收音 10 秒；连续静音 0.7 秒判说完（旧版这些值写死，VAD 阈值 0.5）。
